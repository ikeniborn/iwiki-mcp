Распределённая публикация code graph — результаты внедрения

Тема postgres-code-graph-distributed-indexing. Один локальный индексер строит граф из checkout и публикует неизменяемый снапшот в SQLite, напрямую в PostgreSQL или через аутентифицированный удалённый MCP; сервер без checkout отвечает на запросы из активного снапшота.

4. Влияние на систему

ОбластьИзменение поведенияРиски и последующие шаги
Поверхность MCP25 → 29 инструментов: добавлены четыре инструмента публикации; wiki_code_status, wiki_code_search, wiki_code_context под PostgreSQL больше не отвечают unsupported_storageКлиенты, полагавшиеся на прежний отказ, увидят рабочий ответ. Инструменты публикации доступны только аутентифицированному hosted-вызову с записываемым primary
Схема базыМиграция 5: таблицы графа, гранты рантайм-принципалов, RLS без FORCE, три SECURITY DEFINER-функцииОткат только через закреплённый артефакт compat/postgres-v4-runtime-guard; сырой коммит до code graph бинарём отката не является
Выпуск токеновtoken create требует --hosted-principal ROLE и проверяет именно эту роль до генерации материалаСуществующие процедуры выпуска нужно обновить: без флага команда завершится ошибкой
Индексацияwiki_code_index на сервере без checkout возвращает source_unavailable; при publish_mode ≠ sqlite результат содержит вложенный отчёт publicationСессия и снапшот не создаются, пустой снапшот исключён
Markdown и ссылкиКаждая авторитетная запись страницы увеличивает markdown_generation в той же транзакции; ссылки code-to-wiki выводит цельИзменение Markdown во время открытой сессии даёт snapshot_conflict — публикацию нужно повторить целиком
СекретыЭндпойнт и токен MCP читаются только из окружения и отсутствуют в repr, статусе, логах и ошибкахЗначения обязаны приходить из менеджера секретов; в .iwiki.toml они запрещены
Локальный кэш SQLiteПринимаются два профиля схемы v2; профиль публикации несёт авторитет готовности во внутренней таблицеПеред откатом на бинарь до публикации нужен сохранённый legacy-снапшот или переиндексация
БенчмаркОтчёт получил секцию Publication с режимом, ревизией, временем, пиком кучи и границами батчейПотребители JSON-отчёта должны допускать новый ключ
