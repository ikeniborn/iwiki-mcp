Суть: однопроходный RAG-конвейер Telegram-бота заменён агентным циклом — модель сама вызывает read-only инструменты search_wiki / read_section по протоколу OpenAI tool calling, отбирает и дочитывает секции, синтезирует ответ с атрибуцией page#heading. Провайдер без tool calling детектируется probe-запросом на старте (и демоцией в рантайме) — такой процесс работает по прежнему однопроходному пути без ошибок для пользователя.

5. Схемы

Отложенные minor-замечания финального ревью (6)
  1. Неканоничная форма транскрипта при параллельных tool_calls (N пар вместо одной assistant-записи) — кандидат на follow-up.
  2. WARNING демоции без structured extra-полей (spec §6 form drift) — кандидат на follow-up.
  3. Двойной учёт фиксированного промта в бюджете / неучёт JSON-аргументов — ограничено, поглощается запасом ratio и overflow-рельсой.
  4. Калибровка ratio с агентных completions слегка пессимизирует single-pass бюджет (безопасное направление, клампится).
  5. Дублирующий вызов стадии «Searching wiki» на пути демоции — косметика.
  6. Repo-wide flake8 падает на файлах вне ветки (унаследовано от base, не регрессия).
