4. Влияние на систему

КомпонентИзменение поведенияРиск / follow-up
indexer.py · runtime.py
состояние снапшота		 Снапшот в dirty сохраняет счётчики и диагностику (раньше — обнулялись навсегда до полного ребилда). metadata_reconstructed остаётся только для настоящей порчи или записи в обход хелпера. Окно между SQL-записью и публикацией JSON даёт транзиентное расхождение, чинится следующим переходом — разрешено спекой R1.
fingerprint.py · discovery.py
свежесть		 Правки в исключённых путях (worktrees, кэши) и обычные wiki-записи больше не переводят ready-снапшот в dirty. На первом апгрейде развёрнутая база с «грязью» в исключённых, но не gitignored путях один раз пересоберётся — самоизлечимо.
runtime.py
контекст		 wiki_code_context восстанавливает грязный граф тем же ограниченным авто-ребилдом, что и поиск; сбой lease селекторов отдаёт граф с предупреждением вместо пустого stale. Окно между двумя захватами селекторов может отставить wiki_pages на одну правку — самоизлечимо, неустранимо внутри предписанного порядка. Худшая латентность примерно удваивается, когда случается ребилд.
config.py · context.py · server.py
диагностика		 Каждый invalid_config называет виновное поле через единый идентификаторный шлюз; текст исключений, значения, пути и окружение туда попасть не могут. Форма ответа расширена ключом field — клиенты, сверяющие точный набор ключей, увидят новый ключ.
query.py · postgres/codegraph.py
поиск по пути		 Варианты написания префикса дают тот же результат, что канонический; хвостовой слэш по-прежнему сужает до одной директории. Прежнее (нешипнутое) поведение со срезанным слэшем было шире — восстановлен контракт спеки.
application.py · mcp_adapter.py
маршрутизация чтений		 read_mode выбирает читателя: sqlite (по умолчанию, поведение байт-идентично прежнему), postgres и mcp читают опубликованный снапшот. Один режим, без фолбэков. Развёрнутый .iwiki.toml с read_mode = "mcp" при апгрейде тихо переключится с локальных чтений на удалённые. В mcp-ветке заданный вызывающим languages всё ещё сверяется с локальным конфигом — запарковано с рулингом.
Измерение по метрике здоровья (F-001). Латентность happy-path context(include_wiki=True) на ready-снапшоте: 15–23 мс на пяти сэмплах в трёх прогонах, медиана ≈ 17 мс. Закреплена граница 200 мс как сторожевой порог на незапланированный ребилд. Команда: uv run pytest -q tests/codegraph/test_linking.py -k well_under_the_rebuild_budget.
